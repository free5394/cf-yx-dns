# 2. 差量同步先增后删

日期：2026-10-16
状态：已接受

## 背景

差量同步里，新增与删除往往同时存在（目标 IP 换了一批）。两件事的顺序决定了同步过程中这个记录名的解析是否可用：如果先删后增，删除完成到新增完成之间存在一个窗口，名字下可能没有任何可用记录。

也要决定失败怎么处理：Cloudflare 的 DNS 记录接口没有事务，一次同步里第 k 条失败时，前 k-1 条已经生效。

## 决策

1. **先新增全部缺失记录，再删除全部多余记录**。
2. **单条失败不中断其余条目**：每条新增/删除各自捕获失败，成功与失败分别收集；失败逐条上报（推送正文里明确标出「失败: …」）。
3. **任一条失败则以非零退出码结束**，让工作流能把这次执行标记为失败。
4. **不做回滚**：不尝试撤销已经生效的新增或删除。

## 后果

- 同步过程中该记录名始终保有解析：新增阶段是超集，删除阶段收敛到目标集合。
- 中途失败会留下「新旧并存」的超集。这是刻意选择：超集仍可用，重复执行下一次会收敛；回滚反而可能删掉刚验证可用的新记录。
- 失败不会把成功一起抹掉，因此推送正文里同时出现成功项与失败项是正常现象。

## 备选方案

- **先删后增**：放弃。删除与新增之间存在解析为空的窗口，正是本工具要避免的中断。
- **失败即中止并回滚**：放弃。没有事务语义的保护下，回滚本身也可能失败，且会让一次同步的成败变得难以判断；宁可留下超集，也不做半吊子的补偿。
