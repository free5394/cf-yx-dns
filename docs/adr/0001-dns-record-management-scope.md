# 1. 只管辖 A/AAAA 记录，并拒绝空目标同步

日期：2026-10-16
状态：已接受

## 背景

一个记录名下可能同时存在多种类型的记录：本工具写 A/AAAA，但别人（或历史配置）可能在同一个名字下放 CNAME、TXT、MX。差量同步要决定「什么算多余」，这个判断直接决定工具会不会删掉不该删的东西。

同时，优选 IP 来自第三方页面：页面改版、反爬、网络故障都可能让解析结果为空。如果此时仍然按「现有记录集合减目标集合」执行，结果就是把该名字的解析全部删掉。

## 决策

1. **只管辖 A/AAAA**：读取现有记录时按类型收敛查询，只取 A 与 AAAA；其他类型的记录不读、不比较、不删除。
2. **空列表护栏**：目标 IP 集合为空时拒绝整个同步，一条记录都不新增、不删除，并以失败退出。
3. **重建时沿用代理状态**：删除旧记录、新增新记录时，沿用该名字下同类记录的代理（proxied）状态；取值不一致时不猜测，退回 Cloudflare 默认（DNS-only）并告警。

## 后果

- 记录名下的 CNAME/TXT/MX 永远不会被本工具清理，即使它们已经过期 —— 清理它们需要人工操作。
- 上游真的想清空解析时，工具会拒绝执行，这是刻意的：清空必须由人来表达。
- 代理开关在同步前后保持一致；「现有同类记录代理状态不一致」这一种情况会退化为 DNS-only，并在日志里说明。

## 备选方案

- **全量重建**（每次删除全部现有记录再按目标新增）：放弃。它会在同步期间让解析中断，也会误删不属于本工具管辖的记录类型。
- **按 `name` 读取后再按类型过滤**：放弃。多取的数据本身无害，但「读到了却不该删」的判断容易在后续改动里失守；在查询层就把管辖范围钉死更稳。
