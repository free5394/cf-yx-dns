# 复审归档（Code review archive）

本仓库把每轮代码复审的结论落盘到 `reviews/`，让「返工轮次」与「口径不符次数」有可机械统计的采集入口。

由来：F7 研究（票 #7）发现这两个指标**不可执行**——不是样本少，而是仓库里**没有任何复审报告**，注册的采集入口本身不存在（[?] 分支 `research/f7-rework-metrics` 的 `research/f7-rework-metrics.md` §二、§九 a）。票 #10 据此把归档定成约定，并给出统计脚本。

## 放哪、怎么命名

- **目录**：仓库根 `reviews/`，只放复审报告，不放别的东西。
- **文件名**：`reviews/YYYYMMDD-<对象提交短哈希>.md`，例 `reviews/20261111-c571466.md`。
  - 日期是报告落盘当天（本地时区）。
  - 对象提交是**被评审范围里最新的那笔**提交（范围本身写在正文元信息里）。
  - 同一个提交同一天复审两次（打回后的复评）：第二份加 `-r2`，第三份 `-r3`。
  - 文件名不符合这个形状，`tools/review_stats.py` 直接判不合格。

## 谁落盘

**Lead 落盘。** 派出去的评审子代理只回正文（纯文本），不写文件——子代理沙箱常常写不进工作区，口径责任也应该只落在一个地方。子代理提示词里写明「只读 + 纯文本报告 + 禁止 dsh-ui 围栏」。

## 什么算一份合格报告

正文必须有四行元信息（`tools/review_stats.py` 按标签逐行解析，缺一个就判不合格）：

```markdown
- 对象提交：\`<完整 40 位提交号>\`
- 评审范围：\`<基点提交>..<对象提交>\`
- 评审者：<谁评审、怎么派发>
- 判定：通过 ｜ 打回 ｜ 拒绝
```

- `判定` 只能取词表里的一个词，不加别的字；`打回` 与 `拒绝` 计入返工轮次分子。
- `评审范围` 必须是 `基点..对象提交` 的形式（一次复审对账一个提交范围，不是「一堆改动」）。

正文必须有 `## 逐条 finding` 小节，表头固定六列：

| 编号 | 严重度 | 类别 | 位置 | 问题 | 处置 |
| --- | --- | --- | --- | --- | --- |
| F1 | P2 | 口径不符 | `docs/agents/code-review.md:12` | 示例行，真报告里换成本次 finding | 已修 `abc1234` |

- **严重度**取词表 `P0` / `P1` / `P2` / `P3`（沿用本仓库既有写法）。
- **类别**是自由文本；凡是「文档里的数字、口径、能力声明与实际不符」一律写 **`口径不符`**——它是被统计的那个词，换成同义词就数不到。
- **位置**写到文件与行号（`路径:行号`），后来者才复现得了。
- **处置**写返工落在哪笔提交；不修的写 `不修` 并说明理由；没修完的写 `待修`。
- 没有 finding 时表体留空，**不要写占位行**——占位行会被当成 finding 计入统计。

正文结尾要有 `## 判定结论` 小节：一句话说清这个范围能不能收口。

## 怎么数

```bash
uv run python tools/review_stats.py                  # 统计 reviews/ 全量
uv run python tools/review_stats.py --since 20261111 # 只算文件名日期不早于该日的报告
```

沙箱里 `uv` 可能建不了自己的缓存，可换 `.venv/Scripts/python.exe tools/review_stats.py`。

输出两条分子，口径固定、不可事后更改：

- **返工轮次分子** = 判定为「打回」或「拒绝」的报告份数；**分母** = 同一窗口内的报告总份数。
  这是「返工轮次」的四种读法里唯一能从报告本身机械读出的一种（口径乙：复审-打回事件数）。一次打回产出多笔返工提交时，分子仍记 1——按事件数，不按提交数。
- **口径不符次数分子** = finding 表里「类别」列等于 `口径不符` 的行数；**分母** = 同一窗口内的 finding 总条数。

报告不合格（缺元信息、判定不在词表、表结构不对）或目录为空时，脚本退出码 1——采集入口坏掉要当场报出来，不能静默返回 0。
