## 〇、口径声明（先声明，再算）

三条指标的定义与采集入口照抄 #7 正文「衡量口径预注册（2026-11-09）」。**注册的采集入口有两处不可执行**：

因此：下文所有 before / after 数字都带口径标签，**未标口径的数字不得引用**。

3. **唯一不含切分选择的事实**：CI 首跑失败率分子 = 0（5 次运行全 success）。

5. **未改写预注册验收标准**（保留「事后不得改口径」的纪律）。本条**不是**「已验证减少返工」，而是「按设计不可达」。

## 七、预注册协议自身的缺陷（可直接改）

1. **基线是「0（无样本）」** → 没有对照臂，数学上不可能算出「减少」。要么先测 before 窗口，要么放弃「对比」、改成绝对计数台账。
2. **采集入口依赖一个不存在的归档**（「复审报告」）→ 指标一、三不是样本不足，是**不可执行**；换用提交正文等于换指标定义，必须在结论里显式声明。
3. **CI 口径看不到开发分支**：注册命令 `--branch main` + `ci.yml` 只覆盖 `main`，测不到本轮开发的 CI。
4. **「返工轮次」没定义分母**（条目 / 轮 / 链），四种数法方向不一致；「条目」的权威边界也没定义。
5. **「口径不符」没有判定标准**：谁判、什么算一条、存量问题算不算，都没写。
6. **「下一轮」没定义**：是「改进落地后的那一轮」，还是「预注册之后的那一轮」？两者不是同一轮（§八）。
7. **失败记录可被抹掉**：`--amend` + force-push 会覆盖旧 run。

## 九、若仍要衡量，建议改成（按性价比排序）

- **a. 让复审报告进仓库**：每次复审落盘 `reviews/<日期>-<对象提交>.md`（纯文本）——指标一、三才能机械统计，也才不用事后重建。
- **b. 修 CI 口径**：`ci.yml` 的 `on.push` 扩到所有分支（或加 `workflow_dispatch`），统计改用 `gh run list --json` 全量拉取。
- **c. 定义两个边界**：`CODING_STANDARDS.md` 里写清「什么叫一个条目 / 一次返工」与「口径不符」的判定标准、记录位置。
- **d. 要因果判断就做受控对照**：同一类任务（例如「文档回填」）各做一次 before / after，两侧都归档复审报告。否则永远只有 n=1 的相关性，答不了「是否真的减少」。
